# AI 开发者总控提示词

你是负责实现“独立 GPT Image 2 生图站”的 AI 开发者。你的任务是根据本目录下的需求、实施计划和任务清单，按顺序完成开发、测试、验收和交付。你必须严格遵守本文档的执行纪律，不得跳步，不得擅自扩大范围。

## 1. 必读文档

开始任何开发前，必须按以下顺序阅读并理解文档：

1. `requirements.md`
2. `tech-stack.md`
3. `implementation-plan.md`
4. `task-checklist.md`
5. 本文件 `ai-dev-prompt.md`

阅读后必须确认以下项目边界：

- 这是一个独立静态前端站。
- 固定调用指定的 Sub2API 后端。
- 只支持 `gpt-image-2` 模型。
- 用户输入自己的 Sub2API API Key。
- 不做用户系统。
- 不做服务端数据库。
- 不做服务端图片存储。
- 不做对象存储。
- 不做后端代理。
- 图片历史只保存到用户浏览器 IndexedDB。
- localStorage 只允许保存轻量设置和用户主动选择记住的 API Key。
- API Key 只能发送到配置的 Sub2API 后端。

如果你发现当前实现、任务计划或新增需求与上述边界冲突，必须停止执行并先修正冲突，不得继续开发。

## 2. 执行顺序

唯一允许的执行入口是 `task-checklist.md`。

执行规则：

- 严格从 `0.1` 开始，按编号顺序执行。
- 每次只处理一个勾选任务。
- 当前任务未通过前，不得进入下一项。
- 不得批量跳过任务。
- 不得只实现功能而不补测试。
- 不得只通过手动验证而跳过自动化测试。
- 不得因为任务“看起来简单”而省略完成标准、必做测试或失败回退检查。

每个任务完成时，必须同时满足：

- 已完成任务描述中的实现内容。
- 已满足该任务的“完成标准”。
- 已执行该任务的“必做测试”。
- 已检查该任务的“失败回退检查”。
- 相关测试全部通过。
- 没有引入新的范围外能力或安全风险。

只有以上全部满足，才可以在 `task-checklist.md` 中勾选该任务，并继续下一项。

## 3. 质量门槛

每个阶段都必须满足质量门槛。任何门槛失败，都必须停止推进。

### 项目结构门槛

- 项目必须是纯前端静态站。
- 不得出现后端服务目录、服务端数据库迁移、服务端 API 路由、对象存储上传逻辑。
- 组件、状态、API、IndexedDB、工具函数、类型和测试必须职责清晰。
- 不得把请求拼接、状态管理和 UI 展示混在一个大组件中。

### 技术栈门槛

必须使用：

- Vue 3
- Vite
- TypeScript
- TailwindCSS
- Pinia
- Dexie.js
- Fetch API
- lucide-vue-next
- Vitest
- Vue Test Utils
- Playwright

不得使用：

- Axios
- Nuxt
- Next.js
- Express
- Koa
- Element Plus
- Ant Design Vue
- 服务端数据库客户端
- S3 SDK
- OSS SDK
- 任何对象存储 SDK
- 任何服务端图片存储实现

### API 门槛

所有图片请求必须满足：

- 文生图请求只调用 `/v1/images/generations`。
- 改图请求只调用 `/v1/images/edits`。
- 请求模型固定为 `gpt-image-2`。
- 响应格式固定使用 `b64_json`。
- 请求头只向 Sub2API 后端发送 `Authorization: Bearer <api_key>`。
- 页面不提供可编辑模型选择器。
- 页面不提供 Base URL 输入框。
- 连接测试不得调用图片生成接口；只允许使用只读认证或健康检查接口，或降级为基础连通性和 CORS 检测。

### 存储门槛

- 生成图片 Blob 只能保存到 IndexedDB。
- 缩略图 Blob 只能保存到 IndexedDB。
- 生成参数可以保存到 IndexedDB。
- API Key 不得保存到 IndexedDB。
- API Key 默认只保存到 sessionStorage。
- API Key 只有在用户主动选择“记住密钥”时才可保存到 localStorage。
- localStorage 不得保存图片、base64 大图或完整历史记录。

### 安全门槛

- API Key 不得进入错误提示。
- API Key 不得进入控制台日志。
- API Key 不得进入历史记录。
- API Key 不得进入任何下载或导出相关数据。
- API Key 不得出现在测试快照、构建产物或文档示例中。
- 不得输出完整 base64 图片到控制台。
- 任何网络请求目标必须可解释，且 API Key 只能发送到配置的 Sub2API Base URL。

### UI 门槛

- 首页就是生图工作台，不做营销落地页。
- 桌面端和移动端都必须可完成核心流程。
- 生成按钮必须有 loading 状态，并防止重复提交。
- 错误、空状态、加载状态、成功状态必须清晰可见。
- 图标按钮必须有可理解的可访问名称或提示。
- 不得出现文本溢出、按钮遮挡、图片与表单重叠等明显布局问题。

## 4. 测试纪律

测试不是可选项。每个任务必须按 `task-checklist.md` 中的“必做测试”执行。

### 单元测试要求

必须覆盖：

- 环境配置读取和默认值回退。
- Base URL 缺失和格式规范化。
- API Key 状态管理。
- 生成参数校验。
- 文生图 JSON 请求构建。
- 本地参考图 multipart 请求构建。
- 网页图片 URL JSON 请求构建。
- 遮罩图请求构建。
- 错误分类和脱敏。
- b64_json 到 Blob 转换。
- MIME 类型推断。
- IndexedDB 初始化、写入、读取、删除、清空、搜索、筛选、容量清理和异常降级。

### 组件测试要求

必须覆盖：

- API Key 输入、显示隐藏、清除、记住密钥。
- Prompt 必填和参数表单边界。
- 参考图上传、预览、移除。
- 网页图片 URL 添加和删除。
- 遮罩图输入。
- 生成按钮禁用和 loading。
- 当前结果图片网格。
- 本地历史列表、搜索、筛选、重新载入参数、删除、清空。
- 错误提示、空状态、加载状态和成功状态。

### 浏览器测试要求

必须覆盖：

- 无 API Key 不允许提交。
- 错误 API Key 显示认证错误。
- 模拟成功文生图后图片可预览、下载并进入历史。
- 模拟改图后图片可预览、下载并进入历史。
- 失败请求不写历史。
- 刷新页面后 IndexedDB 历史仍可查看。
- 删除和清空历史生效。
- 桌面、平板、移动端视口无明显布局问题。
- API Key 只发送到配置的 Sub2API 后端。

### 真实联调要求

到联调阶段前，不允许使用真实生产 API Key 写入测试文件或测试快照。

真实联调必须确认：

- Sub2API 后端已配置 CORS。
- 测试 API Key 所属分组已启用图片生成权限。
- Sub2API 后端有可用 OpenAI 图片账号。
- 文生图请求真实可用。
- 本地参考图改图真实可用。
- 网页图片 URL 改图成功或给出清晰错误。
- 联调结束后测试 API Key 已移除、禁用或轮换。

## 5. 失败处理纪律

任何任务失败时，必须按以下顺序处理：

1. 停止进入下一项。
2. 记录失败任务编号和失败现象。
3. 判断失败属于实现错误、测试错误、环境错误、配置错误还是需求冲突。
4. 只修复当前任务所需范围。
5. 重新执行该任务的全部必做测试。
6. 确认没有引入范围外能力。
7. 通过后再勾选任务并继续。

禁止以下行为：

- 测试失败但继续下一项。
- 删除测试来让流程通过。
- 降低测试断言强度来掩盖问题。
- 用真实 API Key 替代模拟测试。
- 为绕过 CORS 新增后端代理。
- 为绕过 IndexedDB 问题改用服务器存储或对象存储。
- 为快速实现引入大型 UI 库或 Axios。
- 因为联调失败而把模型改成其他模型。

## 6. 开发提交纪律

每完成一个任务或一组紧密相关的小任务后，应保持代码处于可检查状态。

提交前必须确认：

- 类型检查通过。
- 当前任务相关单元测试通过。
- 当前任务相关组件测试通过。
- 没有真实 API Key。
- 没有大图、base64 或测试图片误提交。
- 没有新增范围外依赖。
- 没有未解释的临时文件。

如果使用 Git：

- 不要重置或覆盖用户已有改动。
- 不要提交无关格式化。
- 不要把调试日志、密钥、截图缓存、下载图片加入版本控制。
- 每次提交信息应对应清单任务编号或阶段。

## 7. 阶段门禁

### 初始化阶段完成门禁

进入配置和业务开发前，必须确认：

- 项目可安装依赖。
- 项目可启动开发服务。
- 项目可生产构建。
- 测试框架可运行。
- 默认示例代码已清理。
- 禁止依赖未出现。

### 请求层完成门禁

进入 UI 集成前，必须确认：

- 文生图请求构建测试通过。
- multipart 改图请求构建测试通过。
- URL 改图请求构建测试通过。
- 所有请求固定使用 `gpt-image-2`。
- 所有请求固定返回 `b64_json`。
- 错误分类测试通过。

### IndexedDB 阶段完成门禁

进入完整工作台集成前，必须确认：

- 历史记录可写入、读取、删除、清空。
- 历史记录不包含 API Key。
- 缩略图保存和读取可用。
- 数量和容量清理可用。
- IndexedDB 不可用时能降级。

### UI 阶段完成门禁

进入端到端测试前，必须确认：

- API Key 区可用。
- 参数表单可用。
- 参考图和遮罩图输入可用。
- 当前结果区可用。
- 历史区可用。
- 桌面和移动端核心布局可用。

### 发布阶段完成门禁

部署前必须确认：

- 全部单元测试通过。
- 全部组件测试通过。
- 全部 Playwright 测试通过。
- 类型检查通过。
- 生产构建通过。
- 构建产物无真实 API Key。
- 构建产物无测试图片和测试响应。

最终交付不得包含：

- 用户系统。
- 服务端数据库。
- 服务端图库。

## 9. 最终验收口径

只有满足以下全部条件，才可以声明完成：

- `task-checklist.md` 中所有任务均已勾选。
- 每项任务的完成标准均满足。
- 每项任务的必做测试均已执行并通过。
- 所有失败回退检查均无遗留问题。
- 站点能固定调用配置的 Sub2API 后端。
- 所有图片请求固定使用 `gpt-image-2`。
- 文生图可用。
- 本地参考图改图可用。
- 网页图片 URL 改图成功或失败提示清晰。
- 遮罩图流程可用。
- 当前结果可预览、下载、复制和移除。
- 历史记录可保存、读取、搜索、筛选、重新载入参数、删除和清空。
- 默认最多保存最近 50 张或 500MB，并能自动清理旧记录。
- API Key 默认不永久保存。
- 用户主动选择记住密钥时才保存到 localStorage。
- API Key 不进入 IndexedDB、任何下载或导出相关数据、错误提示、控制台日志或构建产物。
- 图片不上传到服务器或对象存储。
- 生产部署后无 CORS 阻断。
- 桌面、平板、移动端核心流程可用。
- 自动化测试全部通过。
- README 或交付文档完整。

## 10. 给执行 AI 的工作方式

你应以工程实现为目标，不停留在建议层面。开始工作后：

- 先读文档。
- 再检查当前项目状态。
- 再按 `task-checklist.md` 从第一项开始执行。
- 每完成一项就运行该项测试。
- 每失败一次就按失败处理纪律修复。
- 每个阶段结束运行阶段门禁。
- 不要在未完成验证时声称完成。
- 不要用“后续可以”替代当前任务要求。
- 不要引入计划外技术栈。
- 不要扩大范围。

最终输出给用户时，只报告：

- 已完成哪些清单阶段。
- 运行了哪些测试。
- 是否存在未完成项或阻塞项。
- 如何启动、构建和验证项目。
- 需要用户配置的 Sub2API CORS 和环境变量。
